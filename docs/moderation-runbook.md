# Community moderation runbook

Apply the Code of Conduct using the least restrictive action that protects
participants and public support quality. Do not reproduce offending or
sensitive content in moderation evidence.

## Actions

1. Use a customer-safe saved response or edit request for a correctable
   wrong-channel or conduct problem.
2. Minimize a comment when supported and proportionate.
3. Lock a thread when harmful interaction continues or a resolved thread needs
   protection.
4. Report spam, harassment, abuse, or platform-policy violations through
   GitHub's native controls.
5. Block an account only under the approved organization policy and with
   independent review.
6. Apply repository or organization interaction limits only for an active abuse
   spike, with the narrowest scope, an expiry, a named reviewer in protected
   evidence, and a restoration check.
7. Use collaborator-only Issue creation only as a temporary browser-admin abuse
   fallback; normal verified operation permits ordinary signed-in users.

## Sensitive disclosure

Stop ordinary moderation and use the sensitive-disclosure runbook. Do not quote
or summarize the content. Isolate security reporting from Community workflows,
metrics, and notifications. Editing or deleting a thread does not recover
confidentiality.

## Record

The private moderation record contains the public object reference, reason
class, detection time, proportionate action, short sanitized rationale, owner
role, expiry where applicable, and opaque evidence key. It never copies the
body, personal escalation details, or private destinations.

## Appeal and restoration

A moderator does not decide an appeal of their own action. An independent
reviewer may uphold, modify, or reverse it. Every temporary restriction has an
expiry and a tested restoration step. If the primary moderator is unavailable,
the distinct backup receives notification within the approved escalation
window.
